# 验证、可视化与交付

## 独立验证

使用未参与拟合的每路单帧，保持预先划分的 test 不参与模型选择。验证集选型后再打开最终 test；若根据 test 又调了参数，应改称它为验证集并另找测试数据。

建议逐对、逐雷达报告：

- 参与评估的点数、建立对应的数量和覆盖比例，注明重复对应并非独立样本。
- 点到面绝对残差 median/P90/P95/RMS，以及明确阈值内比例。
- 最近邻欧氏距离分布；不同扫描线密度使其与点到面指标含义不同。
- 无匹配/少匹配的传感器与边，不能只列成功的边。
- 法向方向分布、信息矩阵特征值、共视图连通性；不要把局部秩检查当作全局唯一性或物理误差上界。

固定并公开评估的空间距离和法向阈值，不按点到面残差再次截断后宣称全量误差。对参数候选同时比较残差和覆盖率，避免通过缩小 ROI 隐藏坏点。若只统计高质量平面，明确统计范围，并另外展示全量单帧拼接。

## 反证和稳定性

- **初值扰动**：多次有界平移/旋转扰动后重算，报告是否落入不同局部极小值。数值回到同一解不等于毫米级物理精度。
- **分帧重算**：对不同训练帧独立标定，比较位姿差；可反映静态场景内的重复性，不能替代新场景/实测靶验收。
- **局部切片**：覆盖地面、多个朝向的墙面、近场结构及远处结构。投影重合来自不同深度时，应增加薄切片或平面坐标残差，避免把二维重叠误认成三维一致。
- **装配核对**：安装基线、相对高度、朝向、左右和前后关系。用户确认估计尺寸后记录确认，但不要称其为精密测量真值。
- **闭环/边剔除复算**：移除可疑边后是否大幅改变解；独立的环路约束比只验算由同一组位姿导出的恒等闭环更有意义。

## 交付约定

外参至少包含：reference/source frame、单位、`T_reference_from_sensor`、平移、`quaternion_xyzw`。若提供 RPY，明示度/弧度以及 `Rz(yaw) Ry(pitch) Rx(roll)` 等旋转约定。不随意添加车体原点；用户确认的安装布局近似须按 [base_link 定义](base-link.md) 记录依据，与测量真值区分。

单帧可视化应是每个雷达各一帧的近同期组，不是把训练多帧累积图称为“一帧”。保存消息 ID、frame_id、header、逐点时间范围、组内时间差和预处理过滤条件。

- PLY/NPZ：保留有限有效范围点，按 sensor_id 着色；过滤规则不依赖最终配准残差。保留原始未过滤数据的来源。
- PNG：轴、单位、参考系、传感器图例和可读的显示范围。检查成图是否空白、裁切、图例遮挡或少了雷达。
- HTML：在确需交互查看时使用 Plotly 等绘制可开关传感器的三维点云。内嵌必要 JS，避免依赖外网 CDN；公开显示抽样与完整 PLY 的差异。
- 报告：区分表面一致性、重复性、数值收敛与绝对标定精度。保留误差尾部和数据缺口，不把“中位数 1 cm”改写成“外参精度 1 cm”。

仅要求安装布局或更改 `base_link` 时，按 [3D 坐标轴说明](base-link.md) 显示各雷达本地 XYZ 和明显的车体系，使用与新外参/XML 相同的矩阵。用户只要 3D 就不强制输出 PNG/投影图；仅改参考系不重新训练或宣称精度提高。用户自行视觉检查时保留数值/结构检查，不启动浏览器代验或声称视觉通过。

交付前重新读取 YAML/JSON/CSV；检查矩阵尺寸、有限值、末行、`R.T @ R`、`det(R)=+1`、四元数归一化与一致性。对原始源帧按导出的矩阵重算，逐点对照 PLY/NPZ，核对 sensor_id、数量和哈希。最终重新计算原包 SHA-256。

若用户要求部署文件，按 [静态 TF XML 导出](tf-launch.md) 使用 `scripts/export_tf_launch.py`；parent=reference、child=sensor，跳过参考系自环。先核对本机 publisher 参数格式，不要在验证脚本里启动实际节点。生成配置不等于获准部署。

## 面向用户的打开方式

HTML 内嵌 JS 时无需服务器，可在本地浏览器打开；远程机器先下载文件再打开。一般操作是拖动旋转、滚轮缩放、点击图例隐藏/显示一路、双击图例独显。若采用的绘图库不是 Plotly，先验证实际操作方式再说明。
