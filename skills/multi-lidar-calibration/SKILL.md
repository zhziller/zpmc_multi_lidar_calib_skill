# 多激光雷达静态外参标定

目标是得到有证据支持的 `T_reference_from_sensor`，而不是仅生成看起来重合的图片。适用任意合理路数，不固定为八路，也不预设话题名、线数、车长、安装方向或最终精度。

## 开始时确定范围

- 区分“只检查数据”“估计外参”“复核已有外参”“定义/切换 base_link”“导出现有外参”；检查、换基或格式导出请求不自动升级成修复数据库或重新标定。已有外参定义车体系进入第6节，只需转 XML 进入第7节。
- 先检查工作区和现有工具。记录用户允许写入的目录；原始数据只读，新环境、缓存、临时文件和结果放在允许的位置。安装环境、发布 TF、修改机器人配置是不同动作，不把其中一种授权扩展到另一种。
- 收集数据路径、雷达数量、参考坐标系、静态条件、已有外参/安装图和精度用途。缺少 CAD 初值不一定阻塞，可先做数据驱动初始化；明显尺寸矛盾或不可观测自由度不能靠猜测填补。
- 没有车体测量基准时，先选一路雷达作为参考；不要直接改名成 `base_link`。用户明确同意后，可按安装布局定义近似车体中心，但须与 CAD/测量真值区分。安装点基线与车体外廓尺寸分别核对。

## 按证据推进

### 1. 检查原始数据

读取 [数据检查与提取](references/data-integrity.md)。实际尝试读取/反序列化，不把 metadata 当作健康证明。检查话题、帧数、字段布局、有效点、header/逐点/记录时间及短时静态一致性。

遇到损坏时量化可读数据，记录失败范围与查询方式；不要将不可读消息等同于雷达丢帧或永久丢失。足够的可读静态帧可以继续使用，但报告必须保留数据缺口。

### 2. 先隔离训练、验证和测试

- 在调参前按消息 ID/时间组划分。训练用于拟合，验证用于选择参数，最终测试在参数冻结后使用。
- 保留每路单帧及来源 manifest；不要只保存多帧叠加点云。记录同组扫描时间差及扫描持续时间。
- 数据太少时明确“无独立测试”，不能通过重复同一帧伪造验证集。静态扫描的时间戳相近不证明硬件同步。

### 3. 建立可靠的粗位姿与共视图

读取 [配准与失败判据](references/registration.md)。先观察每路自己的坐标系，识别地面、墙面、近场遮挡和可能倒装/侧装的雷达。

优先连接有可靠共视的邻居，构造连通图，再加入跨车体闭环。可以使用安装粗值、特征全局配准、平面方向或人工确认的对应结构；保留候选的方向、指标和采用理由。重复厂房结构与大面积地面会产生高重叠率的错误解，不能单凭 fitness 选结果。

### 4. 共视裁剪与联合精配准

- 粗位姿可信后，在公共坐标系中裁剪共视 ROI；可以按空间范围/语义结构裁剪，也可以在每轮更新最近邻和法向约束后的对应区域。
- 用平面性与非共线性筛选局部法向，双向点到面残差、稳健权重和逐对平衡减少高密度地面的支配。
- 固定参考雷达，联合优化其他位姿；检查连通性、信息矩阵和弱方向。图连通不代表 6DoF 充分约束。
- 使用随数据调整的多尺度阈值，比较保留验证集上的误差及覆盖率；更小体素或更低训练损失未必更好。

已有可信初值和提取后的 NPY/NPZ 时，可用本 skill 的 `scripts/registration.py` 执行 `refine` 和 `evaluate`。先读 [脚本输入和用法](references/script-interface.md)。它不是全局初始化器、ROS 解码器或一键生产标定系统；不要用全单位阵替代未知初值。

### 5. 独立验证和完整可视化

读取 [验证与交付](references/validation-delivery.md)。至少检查：

- 未用于拟合的每路扫描：逐对共视覆盖率、对应关系数、点到面 median/P90/P95/RMS、最近邻距离，保留长尾和弱雷达。
- 评估不得沿用训练时的残差拒绝阈值来宣称全量精度；公开几何匹配筛选条件及被排除比例。
- 初值扰动、分帧重算、局部地面/墙面切片和安装几何核对；区分数值收敛、重复性、表面一致性与测量真值精度。
- 从近同期的一组扫描输出按传感器着色的完整拼接点云及用户需要的 PNG/离线交互式 HTML。声明预处理及显示抽样，不能按最终残差删点美化。仅要求 3D 安装布局时不强制补投影图或重做点云展示。
- 检查齐次矩阵/旋转/四元数、变换方向、源点到导出点的逐点一致性、雷达齐全性与原始文件哈希。

### 6. 按需定义或切换 base_link

读取 [车体坐标系与 3D 坐标轴](references/base-link.md)。先明确参与定义的雷达、中心/高度规则、正前方和轴向约定；不把某辆车的安装条件当成通用默认值。

当用户确认以下安装条件时，可使用四路主周扫定义：只用四路主周扫，以对角中点定义中心，以前雷达 +X、后雷达 −X 定义前方，最终为 **X前、Y左、Z上**。对角中心对称不等于左右镜像对称；BP 和上方雷达不参与定基准，但仍统一换基、展示和导出。仅改轴向时保留现有原点及 +Z，不重新估计中心或重新标定。

使用 `scripts/define_base_link.py` 和显式布局配置定义车体系；用 `scripts/sensor_layout.py` 绘制离线布局。统一左乘所有雷达位姿，检查雷达间相对变换不变。用同一份新外参生成明显的 `base_link` 和各雷达自身 XYZ 轴的离线网页及所需 XML；保留原标定文件。用户自行检查可视化时，只做数值/结构校验，不声称已完成视觉验收。

### 7. 按需生成静态 TF XML

用户需要类似 `multi_lidar_tf.launch.xml` 的文件时，读取 [XML 导出说明](references/tf-launch.md)，使用 `scripts/export_tf_launch.py` 从现有外参 JSON/YAML 生成。默认采用 `x y z qx qy qz qw parent child` 位置参数，可显式切换新式 flags；文件名按用户要求指定。

保留已确认的参考系和真实 frame_id，跳过参考自环；未提供车体外参或确认车体定义时不补 `base_link`。若已按第6节换基，直接从新 JSON 导出 `base_link` 到全部雷达的星形树。校验生成文件与矩阵一致、ROS XML 可解析，但不启动 TF 发布器。

## 停止和交付边界

如果共视图断开、只有单平面约束、初值多解无法区分、装配尺寸矛盾或独立验证明显变差，保留已验证子图及候选结果，指出缺失的约束和下一步采集需求。不要输出未经证实的“全部成功”或为凑路数编造外参。

完整标定的默认交付：外参 YAML/JSON、逐帧来源 manifest、逐对/逐雷达指标、单帧 PLY/NPZ、PNG、可离线打开的 HTML、简明中文报告和复现命令；按用户范围裁减。仅换基时交付新外参、定义依据、所需网页/XML 和一致性检查，不重复训练/测试。只有用户要求时才生成部署配置；未经授权不启动 TF 发布器。

遇到参数敏感性、低残差多解或未收敛结果时，读取 [可靠性边界](references/reliability.md)。本 skill 不附带车辆专属初值或真实标定外参。
